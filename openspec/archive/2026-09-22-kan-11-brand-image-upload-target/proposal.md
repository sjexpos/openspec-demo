## Why

KAN-11 is follow-up F1 of KAN-12 and the first HTTP surface over the asset pipeline. Both halves already exist but are unused together: KAN-10 ships `BlobStorage.createUploadTarget(BlobType)` (canonical key `brands/images/<32 hex>` plus a credential-free presigned `PUT` URL), and KAN-12 ships `BrandImage.pending(brand, imageKey)` plus `BrandImageRepository` and the `brand_images.status` lifecycle. Nothing in the system can currently produce a `BrandImage` except a test. This change wires them — resolve the brand, mint the target, persist the `PENDING` row, return the target — and establishes the reusable asset-creation contract (`brand_videos`, `strain_images`, `product_images`, `dispensary_images` copy it in KAN-12 F5), keeping image bytes off the API via client-to-S3 direct upload.

## What Changes

- Add `POST /api/brands/{brandId}/images` returning `201 Created` (D1 closed: `PUT` rejected — the operation is non-idempotent, has no request body, targets a collection URI; `POST` matches `docs/backend-standards.md`, all three existing creates, and KAN-12 follow-up F1). No request body is accepted; the blob key is generated inside the port and never supplied by the caller. `PUT` on the collection URI returns `405` (AC13).
- Response body is a `DataResponse` with exactly three `String` fields — `uploadUrl`, `uploadMethod: "PUT"`, `expiresAt` (ISO-8601 UTC) — and MUST NOT contain `id`, `brandId`, `imageKey` or `status` (D2 closed, AC1). `status` is always `PENDING` (a constant is payload noise); `imageKey` is an internal key scheme; `id` is deliberately withheld, which structurally forces KAN-12 F2 confirmation to the server-side S3 → SQS model and requires widening the `products/`-only notification filter. `String` DTO types are load-bearing, not cosmetic: `JsonConfig` exposes a bare `new ObjectMapper()` with no `JavaTimeModule` (an `Instant` field throws `InvalidDefinitionException`, a `500` on the happy path — the `ErrorResponse.timestamp`-as-`String` precedent applies), and `HttpMethod` serializes as `{"name":"PUT"}`, not `"PUT"`.
- Orchestration order is resolve → presign → persist: brand resolved first (single `findById`; `@SQLRestriction` covers missing and soft-deleted → `404` with `Brand not found with ID: {brandId}`, AC5; no key minted on a bad request, AC7), then `createUploadTarget(BRAND_IMAGE)` (local SigV4 computation, no network call, no object created; `BlobStorageException` → `502 Bad Gateway` with a fixed message via a new `GlobalExceptionHandler` case, no row inserted, no URL/signature material leaked, AC8), then `BrandImage.pending(brand, key)` persisted as `PENDING` (AC2). Transaction rolls back and the URL is never disclosed on insert failure (AC9). This slice cannot create an orphan blob: an undisclosed presigned URL can never be uploaded against; orphans only arise from unconfirmed client uploads (F2/F4's problem).
- D5 dissolved by D2: the service returns `BlobUploadTarget` directly — no ticket/result record, no new `application/services/model/` package, no `docs/backend-standards.md` project-structure change. D3 dissolved by D2: no `Location` header (it would expose the withheld identifier and point at a read endpoint that does not exist until KAN-12 F3). New `BrandImageService` (D6 recommendation: separate service, not a 5th method on `BrandService` — SRP/ISP; confirm/list/delete land next to it) plus `BrandImageApi`/`BrandImageController` and a 3-field response record; D2 structurally neutralises the lazy-`Brand`/`open-in-view` trap (controller never touches the entity, no proxy resolved). No Flyway migration — `brand_images` is correct as of `V0.1.1`; a migration here is a review-blocking smell. No cap on concurrent `PENDING` rows in this slice (D4 recommendation: no auth exists codebase-wide, so a cap is not a real control; accepted risk behind the no-production-exposure gate, F4 sweeps via `ix_brand_images_pending_created`).
- Success response carries `Cache-Control: no-store` (AC10; presigned URL is a bearer capability). URL is never logged, never persisted (row holds only the opaque key, AC12), never in an OpenAPI example (placeholder only), `400` on non-numeric `brandId` via the existing type-mismatch handler with no lookup/presign/insert (AC6). Each call yields a distinct key/row/URL (AC4, non-idempotent by design).
- Bucket CORS rule (`PUT`, app origins, `content-type` allowed header for F12 forward-compatibility) added to `localstack-resources.yml` as a hard prerequisite (A1 answered: caller is browser + mobile app; browser preflight `OPTIONS` fails without it while the whole test suite stays green — highest risk in the ticket; AC14 verified by manual browser check since LocalStack does not enforce CORS). Mobile sizing input: presign TTL vs backgrounded-upload retries feeds F4's retention window. Declared MIME type is deferred to its own story F12 (a contract change to this endpoint: port signature + request body + allow-list `400` + likely migration).
- Out of scope (KAN-12 follow-ups, not re-litigated): upload confirmation `PENDING → UPLOADED` (F2, now forced to S3 → SQS and larger than written — re-estimate); listing/reading + `urlFor(key)` (F3); delete/reclaim/sweep (F4); declared MIME type (F12); size limits/virus scan (F7); auth/rate limiting (gates production); soft-delete cascade; ordering/primary-image.

## Capabilities

### New Capabilities

- None. This change introduces no new spec capability; it composes the shipped `blob-storage` port and `asset-lifecycle` persistence path behind a `brands-management` operation.

### Modified Capabilities

- `brands-management`: add a requirement for creating a brand image upload target — resolve-then-mint-then-persist ordering, `POST` + `201` with exactly `uploadUrl`/`uploadMethod`/`expiresAt` (no identifier, key, or lifecycle state in the response), non-idempotent distinct-key semantics, `404`/`400`/`405` cases, `BlobStorageException → 502` with a fixed non-echoing message, `Cache-Control: no-store`, URL-never-retained, and browser-preflight permissibility.
- `blob-storage`: narrow *Requirement: Scope exclusions* (blocking corrective delta) — the capability itself SHALL NOT expose an HTTP endpoint, while consuming capabilities MAY expose endpoints that orchestrate the port; without this edit the shipped "no HTTP endpoint wrapping the port" scenario contradicts this change and the spec suite becomes false.

## Impact

- **Code**: new `BrandImageApi` + `CreateBrandImageResponse` (3-`String` record) + `BrandImageController` (`Cache-Control: no-store`, ticket-to-DTO mapping), new `BrandImageService`/`BrandImageServiceImpl` returning `BlobUploadTarget`, `GlobalExceptionHandler` gains `BlobStorageException → 502` (first HTTP exposure of the port; fixed client message, key-only logging), `localstack-resources.yml` gains bucket `CorsConfiguration`. Explicitly untouched: `BrandImage`, `BrandImageRepository`, `AssetStatus`, `BlobType`, `BlobStorage`, `S3BlobStorageAdapter`, `BrandService`, `BrandRepository`, `JsonConfig`, no migration, no new package — diffs there mean scope creep.
- **APIs**: one new route `POST /api/brands/{brandId}/images` (`201` + 3-field body; `400`/`404`/`405`/`502` per contract); OpenAPI `@Tag("Brand Images")` with placeholder-only `uploadUrl` example; template for five remaining asset tables (generic `AssetUploadService<T>` deferred to 2nd/3rd occurrence per DRY Rule of Three).
- **Database**: zero migration; one indexed PK `SELECT` + one `INSERT` per call; reads/writes covered by `V0.1.1` indexes; no new index.
- **Security/ops**: bearer-capability handling (`no-store`, HTTPS outside local, never logged/persisted/exemplified); key generated server-side (no traversal/guessing); short `aws.s3.presign-ttl`, no per-endpoint override; `502` leaks no upstream detail; response exposes no identifier/key scheme (no enumeration, no coupling). Open and unmitigated: no auth anywhere — unauthenticated capability minting, MUST NOT reach production; browser reachability makes this the ticket where the gap stops being theoretical. Docs: `docs/data-model.md` (§9 write path), `docs/backend-standards.md` (asset-creation convention, `502` mapping, presigned-URL handling, CORS-as-DoD rule), `README.md` endpoint list if present.
